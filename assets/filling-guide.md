# 设计工作簿填写说明

工作簿四张表均为使用者设计输入。可以分批填写，不要求一次完成。Agent 只读设计，不评价平衡，不调整效果与数值。模板没有“卡牌-统计”。

## 字段

| 工作表 | 列顺序 |
| --- | --- |
| 卡牌 | key、名称、稀有度、类型、费用、描述、升级后费用、升级后描述、备注 |
| 关键词 | 关键词、描述、备注 |
| 状态 | key、名称、描述、关联卡牌 |
| 遗物 | key、名称、遗物池、稀有度、描述、备注 |

有内容的行应填写 key/关键词和描述；卡牌同时填写名称、类型、稀有度和费用，状态填写名称，遗物填写名称、遗物池和稀有度。不完整条目保留待补，Agent 不猜测。
空行跳过。不要使用公式代替设计值；费用写数字或 X，0 是有效数值。
不要改表头或增加解释行。长文本可换行，样式预留 30 行，可继续向下填写，读取工具不限 30 行。

key 使用 PascalCase，例如 SparkStrike，在本类别中唯一。卡牌和状态可以有同一个 key。显示名称变化不改变 key。
关键词表不新增 key 列；Agent 在工程侧建立名称到实现 ID 的对应关系。
描述忠实写出期望行为。目标、触发时点、次数、持续时间、取值时机存在歧义时，Agent 会询问。备注同样参与实现，不是忽略字段。

升级后费用和描述为空时先核对项目已约定的空值含义，不自动解释为“不变”或“不可升级”。新内容尚无约定时由使用者澄清。自定义稀有度、类型或特殊费用按当前 API 和设计确认，不由模板进行平衡评价。

遗物池必须对应 moddev.json 的 pools 配置，例如“通用”映射 SharedRelicPool；自定义角色池由 Agent 建立后添加配置。初始遗物也遵循该列，同时按项目文档绑定角色。

状态关联卡牌允许空白或“无”。支持卡牌 key、唯一当前名称、名称（Key）。括号中的 key 优先。多重匹配报告问题，不猜测。
关联只用于按需生成图标，不自动推断状态的行为或绑定逻辑。无关联时保留手工图标。

## 填写示例（不属于待实现数据）

卡牌：SparkStrike / 火花打击 / 初始 / 攻击 / 1 / 对一名敌人造成6点伤害。 / 1 / 对一名敌人造成9点伤害。 / 空白

关键词：余势 / 下一张攻击牌额外造成2点伤害。 / 用于共享悬浮提示；具体消耗规则见机制文档。

状态：Momentum / 余势 / 下一张攻击牌额外造成{}点伤害。 / SparkStrike

遗物：PracticeBadge / 练习徽章 / 通用 / 初始 / 战斗开始时获得3点格挡。 / 空白

这些数值只是字段示例，不是推荐设计。状态文本中的 {} 必须由 Agent 按已确认含义适配实际本地化变量，不能原样当作有效 API 变量。
初始牌组数量和初始遗物绑定填写 design/character.md，不在表格中添加隐含规则。
