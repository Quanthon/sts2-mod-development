# 发布与可选扩展

## 本地打包

按目标项目清单读取版本；有代码时执行实际工程的 Release 构建，资源按当前方案导出或打包。
依据当版加载器和该类 Mod 要求收集实际需要的代码、资源及清单，不能强制资源方案包含 DLL；不包含设计表、原始素材、开发工具、游戏程序集、其他 Mod 或凭据。
复用项目已确认的打包布局；建立 ZIP 内容清单与 SHA-256，检查版本一致。构建或导出失败不发布旧产物。若临时修改版本，失败时恢复。
打包成功不能替代游戏加载验证。安装说明列出单独安装的依赖。

## 工坊上传搭建

官方上传器： https://github.com/megacrit/sts2-mod-uploader
工作区说明： https://github.com/megacrit/sts2-mod-uploader/blob/main/template/README.md

使用所选官方版本完整发行包，先阅读其 README/--help，不复制示例项目的定制上传器。
分开实现“构建并准备工作区”和“实际上传”。准备操作生成清单、封面和本 Mod 产物，可本地检查。
明确页面资料由本地还是网页维护；仅向上传器提交打算更新的字段，并核对该版本 null/省略值语义。
同样核对 dependencies、封面和 previews 的实际行为，不能假设省略字段/空目录一定保持线上内容。
保存工坊 ID 与备份，后续更新同一条目。首次上传结果不明时查日志和线上条目，确认 ID 后再重试，避免重复创建。
GitHub 源码发布独立于 Steam，不自动提交本地工具、历史、配置或原始素材。

## 数据采集搭建

先问清需要采集的事件与字段、后端归属，再查当前 RitsuLib 数据遥测和保存教程。后端由用户选择，本技能不内置账号或 token。
沿用框架的玩家授权流程，提供拒绝和撤销；调试不能代玩家同意。按需求投影必要字段，不直接上传整个存档。
公开采集 token 与有读取权限的管理密钥分开；管理密钥不进入 Mod 或技能。
记录网络失败、重试和事件去重策略；不要把“最终卡组”解释为“选取率”。
分别检查拒绝、同意、撤销、正常结束、放弃及排除范围。接口成功只证明请求被接收，还需核对后台事件与真实对局。
测试事件明确标识，避免混入正式数据。只在用户请求范围内接入外部服务。

## 其他内容

药水、事件等额外内容按需求查询相应教程，仍使用确认设计、核对接口、实现、验证的闭环。
本技能第一版随包提供四类设计工具；其他内容不要伪装成卡牌行，应按实际任务增加合适输入与验证。
