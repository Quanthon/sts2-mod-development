# 内容实现

从机制文档与设计表提取当前规则，只澄清会产生不同实现的歧义。已有确认信息直接复用。
新行为先定位项目可靠实现、相应教程和当前接口，记录采用的参考及必要适配。资料不足时明确缺口，继续可独立完成的内容。

| 内容 | 核对重点 |
| --- | --- |
| 关键词 | 名称、共享提示或专属预览、引用与稳定实现 ID |
| 状态 | 叠加、触发、消耗/移除、当前数值及图标 |
| 卡牌 | 费用、类型、稀有度、目标、顺序、升级、池和初始绑定 |
| 遗物 | 稀有度、钩子、作用范围、池、图标及初始绑定 |

角色分支默认使用 RitsuLib 当版接口；已有项目沿用适合其版本的结构。参考官方行为时核对完整控制流，再适配 Mod 框架的注册与调用方式。

## 标识和文本

保持已有注册标识。状态 key 与历史类型名不同时记录映射；关键词表的名称在工程侧关联稳定实现 ID，当前工具使用 keyword_ids 配置。
玩家文本按启用语言同步，默认中文和英文。使用当前框架支持的动态变量与升级表达，按语义对应变量，保留设计含义。
数字映射、文件组织和描述格式沿用项目有效约定；随包工具未覆盖的机制由 Agent 实现。

## 实现和验收

先处理共享机制与状态，再接入依赖内容并核对注册、生成路径和资源。未完成骨架保持未注册。
根据设计编写触发、不触发、升级及相关结算边界的场景，按 [公共验证](validation.md) 执行。控制台可用于测试准备，正式效果通过正常游戏路径运行。
