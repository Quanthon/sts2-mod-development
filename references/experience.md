# 提炼依据与使用场景

本技能从一个实际 STS2 RitsuLib 项目的表格驱动开发、教程查证、素材同步、自动调试、ZIP 发布、官方工坊上传和遥测接入经验提炼。
四张设计表字段保持参考工作簿结构，未携带其中的卡牌设计或素材。Python 工具为本技能独立实现，不复制原项目业务脚本。

保留的经验：
- 设计和运行实现分离，差异按稳定标识追踪，备注也要实现审查。
- 教程负责 Mod 接口，官方完整源码负责行为参考。
- 设计快照、静态检查、游戏加载、场景行为分别证明不同事项。
- 图片比较内容；占位图保护正式图；同步写入失败可恢复。
- 新行为用独立断言场景；已有路径避免无意义重复测试。
- 上传准备与实际发布分开，上传结果不明先确认 ID。
- 数据接收成功与真实对局入库分别验证。

没有继承的项目特例：固定角色名与存档破坏许可、固定磁盘路径、强制占位卡图、私有服务配置、项目专属关键词语义和自动效果模板。

## 使用演练

1. 角色从零开发：init --profile character -> 填环境与机制 -> 最小工程加载 -> 实现关键词/状态 -> 填初始卡/遗物 -> diff -> 实现与验证 -> record/accept。卡表可先为空，其他表可独立推进。
2. 局部更新：读取现有配置与记录 -> 按类别/key diff -> 只改对应字段及必要引用 -> 按影响验证 -> record/accept。新增 key 属于完整实现，不因工具没有 C# 生成器而只报告后结束。
3. 不要临时图：记录 defer -> 跳过 placeholder -> 核对框架资源要求 -> 支持的情况下继续实现与验证；确需资源则记录具体阻塞并继续独立工作，不强迫用户改选。

4. 皮肤项目：公共 init -> 确定替换对象和素材 -> 核对资源接口与所需依赖 -> 接入资源 -> 加载及实际画面验收。不创建角色或四类表。
5. 特效/其他需求：公共 init -> 明确触发与表现 -> 查相关资源或补丁接口 -> 实现并验证 -> 按需发布。后续需要卡牌时才 add-content，不重建已有项目。

角色分支保留了原项目已经积累的内容工作流；其他分支提供需求入口与公共流程复用，不宣称所有皮肤/特效接口已实机验证。
上述演练用于检查技能决策；工具单元测试和 CLI 集成测试不代表已经用本技能完成新 Mod 的实际游戏验证。
