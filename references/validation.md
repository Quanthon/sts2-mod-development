# 公共验证与恢复

根据当前改动选择能证明结果的检查，沿用项目可靠工具。

| 改动 | 主要验证 |
| --- | --- |
| 文档 | 内容、格式和引用 |
| 开发脚本 | 相关测试与实际工具调用 |
| C#、注册 | 编译、安装和实际加载 |
| 资源、动画、音效 | 引用、导出及游戏中的实际表现 |
| 本地化 | JSON、变量、启用语言与实际显示 |
| 游戏行为 | 有断言的场景，覆盖发生变化的效果边界 |

已有证据覆盖的相同路径可复用；语义或路径变化后更新相关记录。用户要求跳过测试时保留适用的构建与静态检查，并如实记录未执行项。

## 构建与加载

按实际工程配置构建和导出，核对退出码及本次产物。新增类型、注册或资源通常需要重启；热重载按所用工具支持使用。
首段以加载日志、初始化标识及实际资源表现确认最小 Mod 运行。后续自动行为验证前接通调试状态读取；视觉和音效检查仍需查看或听取实际表现。

## 自动场景

STS2-Agent/MCP 是默认选择，也可复用等效的已验证接口。依据当前接口形成闭环：

    读取状态与可用动作 -> 执行动作 -> 等待条件 -> 检查结果

使用最新状态的目标与索引，按有超时的条件等待；需要改写进度的测试使用已授权存档。
多步场景可用 Python 的 run(test) 接口，或项目已有运行器。通用助手处理机械操作，场景描述具体规则。
断言提供预期、实际及必要前后值，成功返回简明结论。失败保留证据，修复后重复相关检查。

## 记录与继续

在项目需求文档中保存已实现、已验证、待补信息、证据链接和下一步。恢复任务时核对实际文件与记录，继续相关工作。
使用四类工作簿时另按 [内容同步](sync-validation.md) 管理差异和快照；记录和快照用于追踪，不代替实际验收。
