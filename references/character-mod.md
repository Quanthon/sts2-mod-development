# 角色与四类内容

公共环境就绪后使用本流程。新增角色时建立角色、池与初始绑定；只添加内容时沿用现有角色。框架默认参考 RitsuLib，也可适配项目已采用的可靠接口。

## 1. 核心机制

由玩家口头说明或提供文档，Agent 整理到 design/mechanics.md，角色和初始绑定记入 design/character.md。
按 [内容实现](implementation.md) 确认触发、目标、结算、叠加和清除等必要规则，实现并验证关键词和状态。没有自定义机制时直接进入内容表。

## 2. 设计输入

按 [填写说明](../assets/filling-guide.md) 提供卡牌、关键词、状态、遗物四表，通常从初始内容开始，也可以批量提交。
新项目用 init --profile character，已有公共项目用 add-content 补齐缺少的模板，保留已整理的文档。命令细节见 [工具接口](tools.md)。
缺图时询问临时图或暂不提供，沿用玩家选择，并核对实际资源要求。

## 3. 实现与迭代

按 [内容同步](sync-validation.md) 检查差异，按依赖分批完成代码、注册、本地化、素材和工程适用的映射；备注与关联同样参与实现。
对所选范围持续推进，存在歧义的条目单独澄清，其他独立内容继续。设计变化落实到设计来源，代码偏差按已确认设计修复。

## 4. 验证与接受

按 [公共验证](validation.md) 检查相关行为。新语义重新验证，已有可靠路径复用证据。
完成后 record/accept 对应条目；未完成项保留进度。素材工具见 [素材处理](art.md)，试玩、发布和采集使用公共流程。
